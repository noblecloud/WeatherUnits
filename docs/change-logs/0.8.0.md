# 0.8.0

First release since 0.7.1 (November 2022). Three years of work on `dev`, released
as one drop. **Config parameter names are snake_case** — see "Breaking" below.

## Breaking

- **Config and format-spec parameters renamed to snake_case.** Every
  `camelCase` parameter is now `snake_case`, in both `config.ini` keys and
  format specs. `trailingZeros` becomes `trailing_zeros`, `leadingZeroDropped`
  becomes `leading_zero_dropped`, `digitBudget` becomes `digit_budget`, and so
  on. The `max` parameter is renamed and now means what the documentation always
  claimed: a display-width budget in characters, not a decimal cap.
- **`max` is enforced below 1.** A `max` under 1 is clamped, rather than
  silently rendering an empty string.
- **`FormatSpec` accepts `:` as a key/value separator**, not just `=`.

## Formatting

- **`leadingZero` is adaptive.** The leading zero is dropped when it is not
  needed for the budget. This is what makes `max=2, precision=2` coherent for
  precipitation: `.01` is two digits, satisfying both at once, where `0.01`
  needs three and was always over budget.
- **`trailing_zeros`** replaces two dead overlapping booleans. Modes are `off`,
  `'pad'` (pad to the configured precision), `'fixed'`, and `keep`, with
  documented conflict rules between them.
- **`true_zero`** lets an exact zero pad with everything else. By default an
  exact zero stays bare, because `'0'` says the value *is* zero where `'0.0'`
  says "not zero, but rounds to it at this width".
- **`WU_DEBUG`** environment flag enables more detailed `repr` output.

## Fixes

- **`[UnitProperties]` now binds by unit symbol.** Previously only partly bound:
  in `precipitationRate = precision=2, max=2`, `precision` reached
  `Hourly[in/hr]` but `max` did not, so the class ended up with `3`. Any
  `[UnitProperties]` line for a *derived* unit could be half-applied.
- **Config is carried through a refit.** When `bestFit` changes the unit, the
  unit's own settings come with it — `precision`, `digit_budget` and
  `trailing_zeros` belong to the unit being displayed, not the one the value
  started in. Previously a Hectopascal shown as mmHg was formatted with
  Hectopascal's config while wearing mmHg's label.
- **Derived units are localized by converting them**, not relabelling them.
- **`Direction` cardinal/shorten params fixed**, and trailing spaces on
  dimensionless units removed. The budget counts compass components, not
  characters.
- **`Fahrenheit` no longer overrides** the base `showUnit` default.
- **Guards against `None`**: `loadUnitLocalization` with a `None` generic base,
  `localize` with an unset `localizedUnit`, `__findUnitClass__` against a
  `None` unit.
- **`.auto` repaired** on `ScalingMeasurement` — it now composes `localize`
  and `bestFit`.
- **`TypedLimits`** handles infinite values better.
- **Better value precision handling** and hash value generation.
- **Degree sign is now U+00B0**, not masculine ordinal indicator U+00BA.
- Format-spec regexes marked as raw strings.
- Config separator overrides resolved once; the unused property dropped.

## Compatibility

- **Python 3.12, 3.13 and 3.14 supported.** The constraint is now
  `>=3.10,<3.15`.
- Comparison logic and several Python 3.12+ compatibility fixes.
- Bytecode and `.DS_Store` untracked.

## Housekeeping

- Dead-code sweep: 2 deleted, 3 kept, 1 repaired.
- A `tests/` suite exists (143 tests) and a CI workflow runs it.
- Added `docs/formatting.md`, a verified formatting reference, and
  `docs/parameter-audit.md`.
