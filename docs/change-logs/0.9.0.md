# 0.9.0

**WeatherUnits is now unitcorn** 🦄. Same library, new name: the general-purpose
parts — length, mass, time, bytes, and the derived-unit algebra — outgrew the old
one, and the weather part was always in the config. This release also carries
everything merged to `dev` since 0.8.0.

## Breaking

- **Renamed to `unitcorn`.** The distribution is `unitcorn` and the import is
  `import unitcorn`. Every module keeps its path under the new name
  (`WeatherUnits.length` is `unitcorn.length`).
- **Reading plus reading raises for temperatures.** `Celsius(20) + Celsius(5)`
  has no physical meaning, so it raises unless inside `summingReadings()`. A
  reading minus a reading is a change, and a reading plus a change is a reading.
- **A derived value is one number in its unit.** A window such as 6 mm over 3 h
  becomes 2 mm/h; it no longer leaks into `.numerator` or `__pow__`.
- **`Percentage` reads its scale from the caller.** `Percentage(0.1)` was always
  taken as a fraction, so a source reporting 0.1 percent showed 10 percent.
  `isPercentage=True/False` now picks the scale; the size-based guess is for
  literals only.

## Migrating from WeatherUnits

- Replace `WeatherUnits` with `unitcorn` in imports.
- `WU_CONFIG_PATH` and `WU_DEBUG` are now `UNITCORN_CONFIG_PATH` and
  `UNITCORN_DEBUG`. The old names are still read when the new ones are unset.
- A config file may name its local-units section `[unitcorn]`. `[WeatherUnits]`
  still works.
- Loggers are under `unitcorn` rather than `WeatherUnits`, so a logging config
  that names the old logger needs the new one.
- **`WeatherUnits` 0.9.0 is a forwarding shim** (`compat/WeatherUnits`). It
  depends on unitcorn, and `import WeatherUnits` — and every
  `WeatherUnits.*` submodule — resolves to the matching `unitcorn` module, so
  classes are the same objects under both names and old pickles load. It emits
  a `DeprecationWarning` and will not be updated past 0.9. Publish `unitcorn`
  first, then the shim.

## Algebra

- **`*` and `/` across dimensions.** Exponent vectors over m, kg, s and K; the
  result is a named type when one is registered for the vector, a float when
  dimensionless, otherwise a `Compound` that prints its coherent SI unit.
  Same-unit division is a ratio.
- **Type-preserving unary and modulo operators.**
- **Area, Energy and Power** join the algebra, so Power × Time is Energy, and
  irradiance is power per area.
- **A temperature change type**, written with a degree sign.
- Derived values take an optional `period` beside `timestamp`, and a bare number
  on a generic derived class raises a clear `TypeError`.

## Formatting

- **`compact=True`** asks for a unit's label format rather than its reading
  format: `28 29 30 inHg` on a dial face where the reading is `29.92`. A unit
  whose convention keeps its zeros declares its own `_compact_format`.
- `precision=` passed as a keyword is honoured, and a bare comma separates
  format-spec parameters.
- `true_zero` keeps an exact zero bare when a precision is given.

## Fixes

- Rates compare in the same units, and an order compares the digits either side
  has, so `0.0 < 0.1`.
- **Localization finds a unit's config entry on every run.** It picked one
  ancestor from a set, so the result changed with object ids and matched about
  half the time.
- Cached units are dropped when the config is read; separators fall back to `.`
  and `,` when the C locale reports empty ones.
- `Scale.__eq__` no longer raises against another unit family's scale.

## Housekeeping

- The test suite pins `si.ini`, so it no longer depends on the machine's locale.

## Known issues

- **Metric and imperial still do not compare or add.** `Meter(1) + Foot(1)`
  raises and `Celsius(0) == Fahrenheit(32)` is `False`, as in 0.8.0. See
  [same-dimension-regressions.md](../tasks/same-dimension-regressions.md).
